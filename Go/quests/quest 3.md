Pass by Reference:
- **Pass by Value (Передача по значению)** — поведение по умолчанию в Go.
    
    - Функция получает **копию** данных.
        
    - Все изменения внутри функции умирают вместе с ней и не трогают оригинал.
        
- **Pass by Pointer (Передача по указателю)** — то, что ты делаешь в задаче [pointone](https://01.tomorrow-school.ai/intra/qairu/piscinego/quest-03/pointone?event=1081).
    
    - Функция получает **адрес памяти** (`*int`), где лежат данные.
        
    - Функция меняет значение напрямую на месте — в программировании это называют **мутацией на месте** (**In-place mutation** или **Side effect**).

пример из задачи:
```Go
func PointOne(n *int) { 
	*n = 1
}
package main
import ( "fmt" "piscine" )
func main() {
n := 0
piscine.PointOne(&n) 
fmt.Println(n) 
}
```
задача просит чтобы в результате вышло 
$ go run . 
1
$

как мы это решили и зачем нам это нужно?
мы

|**`&`**|.  Перед переменной при вызове.  |**«Дай адрес»** этой ячейки|.  `PointOne(&n)`
|**`*`**|.  В типе аргумента (в круглых скобках).  |**«Я жду адрес»**, а не само число|. `func PointOne(n *int)`
|**`*`**|.  Перед переменной внутри тела функции|**«Иди по адресу и открой ячейку»**|.  `*n = 1`
тоесть

## где это пригодится?
с помощью этого можно результат отдельной функции просто сразу появится в мэйн, тоесть все вещи которые были вычислены в другом месте или функции их результат просто копируется просто таким образом не разгружая мэйн
### 1. Избежать повторных расчетов и дублирования логики (DRY — Don't Repeat Yourself)

Если у тебя есть тяжелая логика — например, загрузка весов модели, парсинг сложного конфига или расчет сложной формулы:
- **Без указателей:** тебе пришлось бы либо заново вычислять это в `main`, либо передавать тяжелые данные туда-сюда, заставляя компьютер постоянно перекопировать их в памяти и нагружать процессор.
    
- **С указателем:** ты вызываешь рабочую функцию один раз, передаешь туда адрес переменной (`&myResult`), функция **напрямую записывает результат в эту ячейку**, а в `main` ты просто сразу делаешь `fmt.Println(myResult)`. Тебе не нужно дублировать код или заново запускать вычисления.
### 2. Изменение общего объекта «на месте» (In-place)

Посмотри на следующую задачу в списке заданий слева — **`swap`** или **`divmod`**:

- В `swap(&a, &b)` тебе нужно поменять местами два числа. Если не использовать указатели, функция поменяет только свои внутренние копии, а в `main` числа останутся прежними.
    
- В `divmod(a, b, &div, &mod)` функция сразу вычисляет и частное, и остаток от деления, складывая результаты прямо по указанным адресам `div` и `mod`. В `main` ты сразу берешь готовые значения без создания кучи промежуточных переменных.

> [!NOTE]+ мини вопросы
> 
> >[!NOTE]+  ### 1. Зачем нужно `n := 0`? Это обманка?
> > 
> > ### 1. Зачем нужно `n := 0`? Это обманка?
> > 
> > Нет, это **не обманка**. Это контрольный эксперимент.
> > 
> > - `n := 0` создает в памяти ячейку (переменную), называет её `n` и кладёт туда стартовое значение `0`.
> >     
> > - Это делается специально, чтобы доказать: в начале там был **ноль**.
> >     
> > - Если бы твоя функция не сработала или работала неправильно, там так и остался бы `0`. Начальный ноль нужен как «белый лист», чтобы увидеть, изменится ли значение на самом деле.
> 
> >[!NOTE]+ ### 2. Почему в `fmt.Println(n)` напечаталось `1`, а не `0`?
> > 
> > Потому что произошло следующее:
> > 
> > 1. Строка `n := 0`: создали переменную `n`, внутри лежит `0`.
> >     
> > 2. Строка `piscine.PointOne(&n)`:
> >     
> >     - Значок **`&`** перед `n` означает: **«не копируй ноль, а передай адрес этой переменной»**.
> >         
> >     - Функция `PointOne` получает этот адрес, заходит прямо в эту ячейку памяти и заменяет лежащий там `0` на `1`.
> >         
> > 1. Строка `fmt.Println(n)`:
> >     
> >     - Программа обращается к переменной `n`.
> >         
> >     - А что сейчас лежит внутри `n`? Там уже лежит `1`, потому что строчкой выше функция `PointOne` физически стёрла ноль и записала туда единицу.
> >         
> > 
> > Именно поэтому выводится `1`. Значение поменяли прямо на месте в оперативной памяти компьютера.
> 
> 
> >[!NOTE]+ ### 3. Почему пишется `piscine.PointOne(&n)`, а не просто `PointOne(&n)`?
> > 
> > Всё дело в разделении файлов по **пакетам (packages)**:
> > 
> > - Твой файл с кодом лежит в пакете `piscine` (вверху файла написано `package piscine`).
> >     
> > - Файл для проверки `main.go` находится в пакете `main` (вверху написано `package main`).
> >     
> > - В языке Go, если функция лежит в **другом пакете/папке**, язык требует явно указать путь:
> >     
> >     Plaintext
> >     
> >     ```
> >     имя_пакета . имя_функции
> >     ```
> >     
> > - Точно так же, как ты пишешь `fmt.Println(n)` (функция `Println` из стандартного пакета `fmt`), ты пишешь `piscine.PointOne(&n)` (функция `PointOne` из пакета `piscine`).


```GO
package piscine

func UltimatePointOne(n ***int) {
***n = 1
}


func main() {
a := 0
b := &a 
n := &b 
piscine.UltimatePointOne(&n) 
fmt.Println(a) 
}
```

В задаче [ultimatepointone](https://01.tomorrow-school.ai/intra/qairu/piscinego/quest-03/ultimatepointone?event=1081) перед нами **«указатель на указатель на указатель»** (`***int`)
Получается цепочка:

`Функция` $\rightarrow$ знает адрес `&n` $\rightarrow$ открывает `n`, видит адрес `&b` $\rightarrow$ открывает `b`, видит адрес `&a` $\rightarrow$ находит саму переменную `a`.

### Почему в решении именно три звёздочки `***n = 1`?

Каждая звёздочка `*` снимает один слой обертки (открывает одну коробку):

- `n` — держит адрес коробки №1 (тип `***int`).
    
- `*n` — мы открыли коробку №1, внутри лежит адрес коробки №2 (тип `**int`).
    
- `**n` — мы открыли коробку №2, внутри лежит адрес коробки №3 (тип `*int`).
    
- `***n` — мы открыли коробку №3 и наконец-то добрались до самого числа `int`!
    

Как только мы добрались до самого числа, пишем `= 1`. Теперь значение по цепочке перезаписано, и когда в конце запускается `fmt.Println(a)`, на экран выводится `1`.


```GO
func DivMod(a int, b int, div *int, mod *int) { 
	*div = a / b //
	*mod = a % b //
}

func main() {
 a := 13 
 b := 2 
 var div int 
 var mod int 
 piscine.DivMod(a, b, &div, &mod) 
 fmt.Println(div) 
 fmt.Println(mod) 
 }

And its output :

$ go run . 
6 
1 
$
```

мы ставим а и б внутрь потому что сситема piscine.DivMod не знает откуда брать их значения и поэтому мы их пишем внутри чтобы он мог виеть их значения из мэйн

```GO
func UltimateDivMod(a *int, b *int) {
	div := *a / *b //
	mod := *a % *b //
	
	*a = div //
	*b = mod //
}

func main() { 
a := 13 
b := 2 
piscine.UltimateDivMod(&a, &b) 
fmt.Println(a) 
fmt.Println(b) 
}

And its output :

$ go run . 
6 
1 
$
```
